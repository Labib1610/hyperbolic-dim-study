# Stage 2.5 — Experiment Tracking & Results Infrastructure

## Context (read first)
Project: **a controlled study of dimension–distortion trade-offs of hyperbolic vs Euclidean embeddings of linguistic hierarchies (WordNet), as a function of hierarchy structure (δ-hyperbolicity).**

Stages 0 (env), 1 (data), 2 (geometry core) are complete and tested. Before we build the trainer, we build the **experiment-tracking layer**, because every training run must write reproducible records into it from day one. This stage is pure engineering — **no math, no geometry, no training logic**. Its job: guarantee that *every number that will ever appear in the paper is reproducible from a saved record*.

**Guiding principle to enforce in code:** a figure or table in the paper is NEVER made from remembered/hand-typed numbers — it is generated by a script that reads a master results table. This stage builds the machinery that makes that possible.

## Environment
- Repo `hyperbolic-dim-study/`, package `src`, venv active.
- Libraries: `pandas`, `pyyaml`, `numpy` available. Use the standard library `json`, `subprocess` (for git hash), `datetime`, `pathlib`.

---

## Objective / Definition of Done
Implement `src/tracking.py` providing a `Run` abstraction and a `results` aggregator such that:
1. Starting a run creates a unique timestamped directory under `outputs/runs/`.
2. The run records: full config, git commit hash, environment info, timestamp, and a human-readable name.
3. During/after a run we can log: scalar metrics, per-epoch curves, artifacts (checkpoints, coordinate files), and figures.
4. On finish, the run appends ONE row to a master table `outputs/results.csv` (and a mirror `outputs/results.jsonl`) capturing config + final metrics, so all runs across the project are queryable in one place.
5. A helper can load the master table into a pandas DataFrame for plotting.
All checklist items pass and `pytest tests/test_tracking.py` passes.

---

## Task 1 — Run directory + identity
Implement class `Run`:
- `Run(config: dict, name: str | None = None, base_dir="outputs/runs")`.
- On init, create a directory: `outputs/runs/<UTC-timestamp>_<shortname>_<8charhash>/` where the hash is derived from the config (so identical configs are visibly related but timestamp keeps them unique). Store as `self.dir` (a `pathlib.Path`).
- Immediately write `config.yaml` (the full config dict) and `meta.json` into that dir.
- `meta.json` must include:
  - `run_id` (the dir name), `name`, `created_utc` (ISO timestamp)
  - `git_commit` — the current commit hash via `git rev-parse HEAD` (wrap in try/except; if not a git repo or git missing, store `"unknown"` and set `git_dirty: null`)
  - `git_dirty` — whether the working tree has uncommitted changes (`git status --porcelain` non-empty), if git available
  - `python_version`, `torch_version` (import torch lazily; if unavailable store `"unavailable"`), `platform`
  - `cuda_available` and `gpu_name` if torch+cuda present else null

## Task 2 — Logging metrics and curves
On the `Run`:
- `log_metrics(dict)`: merge scalar key→value pairs into an in-memory `self.metrics` dict and rewrite `metrics.json` in the run dir. Idempotent, call as often as wanted.
- `log_curve(name: str, values: list[float])`: save a curve (e.g. loss per epoch) to `curves/<name>.json` and also keep in memory. Used for learning curves.
- `log_artifact(src_path, dst_name=None)`: copy an arbitrary file (checkpoint, `.edges`, coordinate `.npy`) into `artifacts/` inside the run dir. Return the stored path.
- `save_array(name, np_array)`: convenience to save a numpy array (e.g. learned coordinates) into `artifacts/<name>.npy`.
- `save_figure(name, matplotlib_fig)`: save a figure to `figures/<name>.png` (dpi=150, tight bbox) AND `figures/<name>.pdf` (vector, for the paper).

## Task 3 — Finishing a run → master results table
- `finish(status="completed")`:
  - write final `metrics.json` and set `meta.json["status"]` and `meta.json["finished_utc"]`.
  - Append ONE flattened row to `outputs/results.csv` and one JSON line to `outputs/results.jsonl`. The row = flattened `{run_id, name, git_commit, status, **flattened_config, **metrics}`.
  - Flatten nested config with dotted keys (e.g. `optim.lr`, `geometry.type`). Use a helper `flatten_dict(d, sep=".")`.
  - CSV appending must be **safe across schema changes**: if new runs introduce new columns, do NOT corrupt old rows. Implement by: read existing CSV (if any) into pandas, append the new row via `pd.concat` with union of columns, write back atomically (write to temp file, then `os.replace`). (Volume is low — a few hundred rows max — so rewrite-whole-file is fine and safest.)
  - `results.jsonl` is append-only (one line per run) as a robust backup that never suffers column issues.

## Task 4 — Reading results for analysis
- Function `load_results(path="outputs/results.csv") -> pandas.DataFrame`. Returns empty DataFrame with no error if file absent.
- Function `filter_results(df, **equals)` convenience to select rows matching column==value (e.g. `filter_results(df, **{"geometry.type": "poincare"})`).

## Task 5 — Atomic write helpers
- Implement `atomic_write_text(path, text)` and `atomic_write_json(path, obj)` using write-to-temp-then-`os.replace`, so a crash mid-write never corrupts a results file. Use these for `results.csv`, `results.jsonl`, `meta.json`, `metrics.json`.

## Task 6 — A tiny end-to-end demo function
- `demo_run()` that: builds a fake config `{"geometry": {"type": "poincare", "dim": 5}, "optim": {"lr": 0.01}, "subtree": "bfs_s50", "seed": 42}`, starts a `Run`, logs a fake loss curve `[1.0, 0.5, 0.2]`, logs metrics `{"distortion_avg": 0.12, "map": 0.87}`, saves a small numpy array as coordinates, saves a trivial matplotlib figure, and calls `finish()`.
- Expose via CLI: `python -m src.tracking --demo` runs `demo_run()` and prints the run dir and the resulting `results.csv` tail.

## Task 7 — Tests (`tests/test_tracking.py`)
- Test a `Run` creates its dir with `config.yaml`, `meta.json` (asserting `git_commit` key exists — value may be a hash or `"unknown"`).
- Test `log_metrics` twice merges (second call adds keys, keeps first).
- Test `finish()` creates/ň appends to `results.csv` and `results.jsonl`; run `demo_run()` TWICE and assert `results.csv` has 2 rows and column union is preserved (add a differing config key on the second to test schema-union safety).
- Test `load_results` returns a DataFrame with the expected rows; test `filter_results` selects correctly.
- Test `flatten_dict({"a":{"b":1},"c":2})` == `{"a.b":1, "c":2}`.
- Use a temp directory (pytest `tmp_path`) as `base_dir`/output root so tests don't pollute real `outputs/`.
